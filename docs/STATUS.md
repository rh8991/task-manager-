# סטטוס הפרויקט

עודכן: 22.11.2026

## מה עשינו היום (22.11.2026)

### שני סוגי משתמשים: מנהל ומדריכים
- **מנהל:** עושה הכול. יוצר, מעדכן ומוחק מדריכים ומערכים. עובד מול הצוותים האחרים (מעבדה, אחזקה, תפעול): הזמנות ציוד ופגישות לפי מערך.
- **מדריך/ה:**
  - **כניסה:** עם קישור שנשלח למייל, בלי סיסמה.
  - **מה רואים:** את כל המערכים ומי עובד עליהם, ואת המשימות שלו/ה.
  - **סטטוס:** מעדכן/ת סטטוס במערכים שלו/ה, "רעיון" או "בכתיבה". ל"נשלח לבדיקה" עוברים רק בשליחת קובץ.
  - **שליחת קובץ:** מעלה את קובץ המערך עם דוח סטטוס (מה הושלם, מה נשאר, חסמים). הקובץ נשלח למנהל במייל כקובץ מצורף.
  - **"בקשה למנהל":** למשל פגישה עם המעבדה.
  - **מה המדריך לא יכול:** למחוק, ולא רואה צוותים, הזמנות ציוד או פגישות. החסימה נאכפת בכללי האבטחה של Firebase.
- **דפים חדשים למנהל:** מדריכים (הוספה גם כרשימה, השבתה, מחיקה, שליחת קישור כניסה שוב) וצוותים (עם איש קשר).
- **מה הוסר:** הלוח הציבורי והפרויקטים. בלי כניסה לא רואים כלום.

### מקום וגיל
- **מקום:** פארק המדע או מוזיאון המדע, עם לשוניות בלוח המערכים.
- **גיל:** ביסודי בוחרים כיתות (א׳–ו׳), וחטיבת ביניים ותיכון כשכבה שלמה.
- **סינון:** לפי מקום וגיל בלוח, ברשימת המנהל ובבודק האלרגיות.

### מיילים
- מייל "ברוך/ה הבא/ה" עם קישור כניסה למדריך חדש.
- מייל לבדיקה עם דוח סטטוס מלא.
- **מכסת מיילי כניסה:** ב-Firebase החינמי אפשר לשלוח רק 5 מיילי כניסה ביום. כשהמכסה נגמרת, הקישור נשלח דרך Brevo.

### תיקון Java
- **הבעיה:** במחשב מותקנת גם Java 8 ישנה שרשומה ב-PATH של המערכת, ו-Firebase נכשל בגללה.
- **התיקון:** הסקריפט `scripts/firebase.cjs` מוצא לבד את Java 21. `npm.cmd run demo` עובד בלי לשנות את ה-PATH.

### בדיקות
- **בדיקות אוטומטיות:** 41 בדיקות יחידה ו-21 בדיקות כללי אבטחה עוברות, וגם ה-build.
- **בדיקה בדפדפן מול האמולטור:** כל התרחישים עברו. כניסת מדריך, שינוי סטטוס, שליחת קובץ עם דוח, בקשה למנהל, אישור מערך ומחיקת מדריך.

## להמשך

1. **לבחון שוב את רשימת הציוד, חלקי המערך והאלרגיות.** לשקול להוריד אותם מהמערך או לפשט אותם.
   - **איפה הם נמצאים היום:**
     - דף המערך אצל המנהל;
     - "המערכים שלי" אצל המדריך;
     - דף ההדפסה;
     - בודק האלרגיות;
     - דוח הסטטוס במייל.
   - **לפני שמחליטים:** לבדוק מה באמת משתמשים בו.
2. **לסדר את הנראות של "המערכים שלי" אצל המדריך.** הדף עמוס: כרטיס מערך עם הרבה טפסים פתוחים.
3. **לבדוק שהנראות נוחה:** במחשב ובטלפון, אצל מנהל ואצל מדריך.
4. **לבדוק שליחת קבצים ומיילים באמת,** לא רק בהדגמה:
   - שהקובץ מגיע מצורף;
   - שקישור הכניסה עובד;
   - שהדוח השבועי מגיע.
   - **צריך בשביל זה:** Brevo מחובר (מפתח SMTP ב-GitHub secrets).
5. **להעלות ל-Firebase.** לפי `docs/SETUP.md`:
   - ליצור פרויקט Firebase;
   - להפעיל Email/Password ו-**Email link (passwordless sign-in)**;
   - להוסיף את הדומיין של GitHub Pages ב-Authorized domains;
   - להגדיר ב-GitHub את המשתנים והסודות (Firebase, Brevo, `ADMIN_EMAILS`);
   - להפעיל GitHub Pages (Source = GitHub Actions);
   - להריץ את ה-workflow ‏deploy.
